# AI Daily News

使用固定模板生成横版中文 AI 日报 HTML。

核心目标不是“每次重新设计一个新闻网页”，而是：  
**在固定报刊模板中，稳定填充当天真实新闻内容，保持高度一致的版式、结构和视觉风格。**

## 最高优先级原则

### 模板优先原则
- 若存在 `assets/template.html` 和 `assets/style.css`，必须优先基于这两个文件生成结果。
- 默认行为是：**只替换内容，不重写布局，不改写视觉风格，不重新设计页面。**
- 除非用户明确要求“改版 / 换风格 / 重做样式 / 改结构”，否则不得修改页面骨架。

### 一致性优先原则
- 输出重点是“稳定一致”，不是“每次都做新花样”。
- 内容可以变化，但页面结构、视觉语言、栏目顺序、主副栏关系、颜色体系、字号层级应尽量保持一致。
- 即使当天新闻结构不同，也应优先通过压缩或扩展文案适配模板，而不是改变模板。

### 真实性优先原则
- 先保证新闻真实，再做排版。
- 不得为了填满页面而虚构新闻、数据、股价、引用或评论。
- 不得输出“整理中”“待补充”“TBD”“略”等占位文本。

### 媒体化表述限制

为了避免页面被误认成正式媒体采编成品，默认禁止或弱化以下表述：

- 原创整理
- 编辑
- 主编
- 记者
- 采编
- 独家
- 内参
- 请勿外传
- 本刊
- 情报社出品
- 第X期（若保留，需同时标注 AI整理资讯）

若模板中保留刊名与期号，必须同时出现以下任一说明：
- AI整理资讯
- AI整理 · 公开信息汇编
- AI生成排版，内容来自公开来源

## 版式一致性规则（最高优先级）

除非用户明确要求“改版 / 换风格 / 重做样式”，否则必须保持日报页面视觉风格稳定一致。

### 固定视觉语言
- 必须使用中文报刊 / 杂志社版式，不得使用科技门户、后台 dashboard、博客卡片流风格。
- 页面底色固定为暖白、米白或浅纸张色。
- 主色固定为黑、灰、暗红；暗红仅作强调色，不得大面积使用高饱和红色。
- 禁止大面积纯黑顶栏、粗重彩色导航、渐变背景。
- 禁止圆角卡片、阴影、按钮式模块、悬浮组件感。
- 分组主要依靠：细分隔线、留白、字号层级、栏宽，而不是色块和组件感。

### 固定页面结构
页面结构必须稳定为：
1. 报头：刊名、副标题、日期、期数、编辑信息
2. 细导航栏：今日要闻、深度报道、国际焦点、科技前沿、财经观察
3. 主头条双栏区：左侧主标题/副标题/摘要/数据带/延展模块/二狗点评，右侧今日快讯/市场脉搏/每日治愈/每日笑料
4. 底部多栏新闻区：固定 4 栏
5. 页脚

### 固定排版规则
- 标题使用偏衬线、报刊感较强的中文字体风格。
- 主标题必须显著大于副标题和正文。
- 正文保持高信息密度，但不能拥挤失控。
- 不同频道必须共享同一套 CSS 规则、字号体系、颜色体系和栅格体系。
- 不得因当天新闻数量或主题变化而改变总体布局。
- 同一天生成多个频道时，所有频道必须像同一份报纸，而不是不同网站拼起来。

### 模板优先原则（排版层）
- 优先复用既定 HTML 骨架和 CSS。
- 若用户未明确要求改版，只替换内容槽位，不重写布局。
- 内容更新不应导致 class 命名、模块层级、栏目位置发生明显变化。
- 不得新增一级模块，不得删除一级模块，不得调整主副栏比例。

## 固定栏目结构

日报固定包含以下五个频道：
1. 今日要闻
2. 深度报道
3. 国际焦点
4. 科技前沿
5. 财经观察

每个频道都应遵循相同的模板逻辑：
- 一个主头条
- 一组关键数据 / 信息点
- 若干延展内容
- 右侧侧栏模块
- 底部四栏补充新闻
- 页脚

不同频道允许围绕同一大主题，但头条角度必须不同。

## 侧栏规则

右侧侧栏固定包含以下模块：
1. 今日快讯
2. 市场脉搏
3. 每日治愈
4. 每日笑料

### 今日快讯
- 用于放 5 到 6 条短新闻。
- 每条一句到两句。
- 优先补充主头条之外的重要信息。
- 不得与主头条正文机械重复。

### 市场脉搏
- 用于展示指数、股价、涨跌幅、融资额、收入、估值、芯片供需等可量化信息。
- 数据必须来自可验证来源。
- 若当天可用数据较少，可减少解释，不得编造数字。

### 每日治愈
- 一句温和、轻盈、适合日报氛围的话。
- 可是短句、金句、轻微鼓励，不要鸡汤泛滥。

### 每日笑料
- 一句轻松、不过火的小幽默。
- 避免低俗、冒犯、攻击性表达。
- 应与 AI / 打工 / 科技语境轻微相关更佳。

## 新闻源文件使用规则
- 新闻来源、来源等级、频道映射、去重、交叉验证、兜底顺序、禁用来源，统一遵循 `references/news-sources.md`。
- 若新闻源规则与一般写作习惯冲突，以 `references/news-sources.md` 为准。
- 调整新闻源时，优先修改 `references/news-sources.md`，不要在本文件重复维护多套来源规则。

## 搜索与选材规则

### 基本原则
- 先真实性，后排版。
- 先一手信源，后媒体转述。
- 先当天新闻，后近一周补充。
- 先权威来源，后一般来源。
- 先去重分配，后写入模板。

### 选材要求
- 优先选择当天或最近几天的高质量新闻。
- 若当天高质量新闻不足，可回退到最近一周，但必须仍具时效性。
- 不同频道之间不得机械重复同一事件。
- 若来源冲突，优先官方或更高可信度来源。
- 不得因为搜不到就填“整理中”“略”“待补充”。

### 搜索时的默认思路
- 头条优先找：模型发布、平台更新、重大合作、监管、融资、财报、芯片与云计算动态。
- 补充新闻优先找：开发者工具、开源项目、行业案例、海外公司动作、市场反馈。
- 若当天国内信息不足，可适当提高国际来源占比，但必须保持五个频道完整。

## 内容写作规则

### 主头条
- 用一条最重要、最有版面价值的新闻作为主头条。
- 标题必须简洁有力度，有“报纸头版”感。
- 副标题用于交代背景或影响。
- 摘要用于解释事件经过、核心变化与影响。
- 不要写得像产品文案或社媒贴文。

### 数据带
- 5 个左右关键数字 / 信息点。
- 例如：价格、参数、时间点、增速、涨跌幅、用户规模、融资额、芯片数量等。
- 只放高价值信息，不要为了凑数塞低价值文本。

### 延展模块
- 3 个左右小模块。
- 适合写：影响、背景、竞争格局、开发者意义、行业联动。

### 二狗点评
- 用轻微口语感、编辑部点评感，总结这条新闻“到底意味着什么”。
- 可以有一点态度，但不能太油、太夸张、太段子化。
- 要像“会说人话的编辑点评”，不是吐槽博主。

### 底部四栏新闻
- 固定 4 栏。
- 每栏一个短标题 + 一段短文。
- 与频道主题相关，但不与主头条重复。
- 排版上要像报刊栏，不像资讯流卡片。

## 模板填充规则

### 必须优先使用模板
- 若 skill 中存在 `assets/template.html`，应把模板视为唯一母版。
- 若 skill 中存在 `assets/style.css`，应保留其为唯一主样式文件。
- 不得另起炉灶重新写一个全新 HTML 结构。
- 不得替换主变量、整体颜色体系、主字号体系、栅格体系。

### 只替换槽位
- 只替换模板中预留的内容占位符。
- 不改变主容器、导航、主副栏、侧栏、底部四栏、页脚的位置关系。
- 不因新闻数量变化而新增、删除或重排一级区域。

### 不足内容的处理
- 若当天新闻不足，优先缩短文案长度。
- 允许减少某个列表项的描述长度。
- 允许让某个延展模块更简洁。
- 不得用占位词顶替内容。
- 不得通过大改样式来掩盖内容不足。

## 输出要求

### 输出格式
- 最终只输出完整 HTML 代码。
- 不要输出解释、分析过程、步骤说明、注释性前言。
- 不要先给提纲再给 HTML。
- 不要混合 markdown 说明和 HTML。

### HTML 要求
- HTML 必须完整可运行。
- 正确包含 `<!DOCTYPE html>`、`html`、`head`、`body`。
- 若采用外部样式文件，应正确引用 `style.css`。
- 若任务要求单文件，也可把样式内联，但默认优先复用 `style.css`。

### 文本风格
- 中文为主。
- 保持“村口情报社”式的编辑部感，但不要过度娱乐化。
- 内容密度高，但语句清晰。
- 不写空话，不写过度营销语。

## 禁止行为
- 不得生成科技门户首页风格。
- 不得生成 dashboard 风格。
- 不得生成博客卡片流风格。
- 不得使用大面积黑底、鲜红导航条、夸张渐变。
- 不得大量使用圆角、阴影、按钮式卡片。
- 不得因为内容变化就重构整体布局。
- 不得编造新闻、编造数字、编造市场数据。
- 不得输出占位内容。
- 不得让不同频道像不同产品页面拼起来。
- 不得为了“更好看”而偏离固定模板。
- 不得使用明显失真的夸张标题党文风。

## 输出前自检清单
在输出最终 HTML 之前，必须逐项自检：

### 版式自检
- 是否仍然是固定报刊风格，而不是门户站 / dashboard？
- 是否仍然保留报头、细导航、双栏头条、右侧窄栏、底部四栏、页脚？
- 是否仍然保持同一套颜色、字号、栅格、模块结构？
- 是否没有新增一级模块、没有改变主副栏比例？

### 内容自检
- 头条是否真实、重要、适合做版面中心？
- 数据是否来自可验证来源？
- 是否有重复新闻跨频道机械复用？
- 今日快讯是否避免重复主头条？
- 是否没有占位文本、没有虚构信息？

### 来源自检
- 主头条是否满足一手信源或双来源交叉验证？
- 是否优先使用了更高可信度来源？
- 是否回溯了原始英文来源，而不是只用中文转述？
- 是否避开了软文、自媒体搬运和未证实传闻？

### 模板自检
- 是否优先使用了 `assets/template.html` 和 `assets/style.css`？
- 是否只是填充内容，而不是重做页面？
- 是否保留了固定槽位和固定结构？

若任一项不满足，应先修正，再输出 HTML。

## 资源文件
若以下文件存在，应按用途使用：
- 模板文件：`assets/template.html`
- 样式文件：`assets/style.css`
- 新闻源规则：`references/news-sources.md`
- 槽位映射：`references/slot-map.md`
- 生产检查清单：`references/production-checklist.md`

使用原则：
- `template.html` 和 `style.css` 优先级最高。
- `news-sources.md` 是唯一新闻源维护入口。
- `slot-map.md` 用于把新闻内容映射到固定槽位。
- `production-checklist.md` 用于最终自检。

## 最终执行闭环
每次执行本 skill，都必须走完这个闭环：
1. 搜索真实新闻与真实数据
2. 按 `references/news-sources.md` 的来源等级筛选候选事件
3. 为主头条做交叉验证
4. 按五个频道分配事件
5. 去重，避免不同频道机械重复
6. 组织今日快讯、市场脉搏、底部四栏补充新闻
7. 按 `references/slot-map.md` 写入模板
8. 对照 `references/production-checklist.md` 检查
9. 只输出最终完整 HTML

任何时候都不要跳过“来源验证”和“模板一致性”这两步。
