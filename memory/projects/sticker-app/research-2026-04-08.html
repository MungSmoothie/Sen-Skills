💡 核心产品概念
CORE PRODUCT

「贴贴手帐」：你的电子手帐贴纸库

把现实世界装进手机：抠图→存贴纸→粘到手帐上

用户用手机拍一张照片（树、石头、路灯、花草等），App 自动识别并抠出主体，保存为透明背景 PNG 贴纸。贴纸存入个人素材库，后续可以把手帐页面当作画布，把贴纸拖进去、旋转、缩放、叠加，组成一张有个人印记的电子手帐。这个想法的核心价值在于——把「看到」→「留住」→「创作」三个动作串联起来，而且贴纸是用户自己拍摄的，有强烈的个人情感和不可复制性。

3步拍→抠→粘
1张照片 N个贴纸
PNG透明背景格式
云端贴纸库同步

📣 二狗点评

俺觉得这个想法最戳人的地方不是"抠图"，而是"自己拍的贴纸"。你去网红地打卡，拍的贴纸跟别人下载的一样——但你自己拍的路边的树、老家的瓦房、校园里的一角，那是独一份的。这个差异化做得好的话，比那些素材库里套模板的手帐App强多了。

核心功能清单

  • P0AI智能抠图（单图→多主体）
  • P0PNG透明贴纸保存
  • P0贴纸素材库（云端同步）
  • P0手帐画布（拖拽+缩放+旋转）
  • P1贴纸分类标签管理
  • P1手帐模板市场
  • P1社区分享（广场）
  • P2AR实景贴纸叠加拍摄
  • P2贴纸纸艺打印机支持
  • P2品牌合作素材库

目标用户画像

  • ①小红书用户，18-30岁女性
  • ②手帐爱好者，有收集癖
  • ③旅行/生活记录者
  • ④亲子记录（孩子涂鸦/手工）

✅ 优势

  • 差异化强：用户原创内容，非素材库模板
  • 情感价值高：自己拍的贴纸，有故事感
  • 用户粘性高：积累贴纸库后不想换平台
  • 小红书天然契合：内容天然适合传播
  • 国内有成功先例：醒图/轻颜的贴纸功能

⚠️ 挑战

  • 抠图精度是核心体验，需选好API
  • 用户拍出好照片的门槛存在
  • 手帐创作有一定学习成本
  • 重量级玩家（醒图/美图）可能跟进
⚙️ 技术方案
TECH STACK

抠图是核心技术，三条路可选

自研代价太高，API 是最优解——问题在于选哪个

抠图（Background Removal）是整个产品的技术核心。精度不够高→贴纸边缘毛刺→用户体验崩溃。目前市场上主流方案有三条路：①开源方案（rembg）②海外商业API（remove.bg/BRIA RMBG）③国内商业API。各有优劣，俺来逐个拆解。

rembg免费开源
BRIA RMBG 2.02026最强商业API
$0.06-0.15/张成本区间
<500msGPU推理速度

方案一：rembg（开源免费）

Python库，一行代码调用：from rembg import remove; output = remove(input)。内置多个模型（BiRefNet/U2-Net等），支持GPU加速。免费，但需要自己部署服务器，GPU成本不可忽视。单张抠图在GPU上约200-500ms。适合：技术强、有GPU资源、能接受运维成本

方案二：BRIA RMBG 2.0 API（推荐）

2026年最强抠图API，精度最高，尤其擅长头发/毛玻璃/半透明物体边缘。在复杂主体上显著优于remove.bg。$0.10-0.20/张，支持batch。边缘精度sub-pixel级别，PNG alpha通道直接输出。适合：追求产品体验、快速上线、商业化

方案三：remove.bg / Photoroom API

老牌方案，稳定可靠，有免费额度。Photoroom额外提供完整的产品图工具链（含阴影/倒影/尺寸标准化），电商场景更强。remove.bg $0.09/张（量大可降）。适合：电商+手帐混合场景

国内方案：阿里/字节/腾讯云

阿里云视觉智能开放平台、腾讯云AI抠图、字节火山引擎等均有类似能力。按量计费，国内访问延迟低，合规性更好。适合：国内用户为主、重视合规和延迟

📣 二狗建议

俺的建议：前期用 BRIA RMBG 2.0 或 remove.bg 快速验证产品体验，等用户量上来了（>1万/天调用），考虑切 rembg 自部署——省成本，也不用担心API涨价被卡脖子。国内版本可以先用阿里云视觉，延迟低、接入简单。

技术架构推荐

  • 前端Flutter / React Native（跨平台）
  • 小程序微信小程序（快速验证）
  • 抠图APIBRIA RMBG 2.0 / remove.bg
  • 存储七牛云 / 阿里云OSS（图+贴纸）
  • CDN阿里云 / 腾讯云（全国访问）
  • 数据库贴纸元数据（标签+来源+时间）
  • 手帐渲染Canvas API / 原生绘图

贴纸存储方案

  • 格式PNG + Alpha通道，JPG仅存档
  • 尺寸原分辨率存OSS，缩略图CDN
  • 命名UUID+时间戳，防止重复
  • 成本50万贴纸 ≈ 50GB ≈ ~¥15/月（阿里OSS）

性能目标

  • 抠图<2秒/张（含上传+推理+返回）
  • 首屏<1.5秒（首页+推荐贴纸）
  • 手帐加载<500ms/页
  • 离线贴纸本地缓存，核心功能离线可用

🍎 苹果原生能力分析
APPLE NATIVE CAPABILITIES

苹果已经有了，这还做不做？

iOS 16+ 的"主体提取"和 iOS 17+ 的"实况贴纸"，会把这条路堵死吗？

大哥问到点子上了。苹果从 iOS 16 开始就内置了 Subject Lift（主体提取）功能，iOS 17 进一步推出 Live Stickers（实况贴纸），可以在相册里直接抠图做贴纸。俺来认真分析一下——这到底是不是竞争对手。

iOS 16+原生"抬起主体"功能
iOS 17+Live Stickers 实况贴纸
VNGenerateSubjectLiftMaskRequest苹果开发者API名称
iOS 18增强视觉搜索隐私

iOS 16+：抬起主体（Remove Background / Subject Lift）

相册里长按任意一张照片的主体，苹果会自动识别并扣出来，点击"拷贝"或"共享"即可获得透明背景 PNG。整个过程在设备上完成，精度极高（苹果自研模型），完全免费。

局限性：①只能保存，不能直接"存入贴纸库"反复使用②不能叠加到手帐画布上创作③没有组织管理功能（贴纸一多了就乱了）④无法跨App使用（在iMessage里能用，但手帐App用不了）

iOS 17+：Live Stickers（实况贴纸）

从 Live Photo（实况照片）提取主体，变成动画贴纸。保存在系统贴纸库里（通过 emoji 键盘访问），可以在 iMessage 和任何支持 emoji 键盘的 App 里使用，包括 WhatsApp、Telegram 等第三方 IM。也可以添加到照片、备忘录、邮件等地方。但必须是 Live Photo，普通照片不能做 Live Sticker。

局限性：①必须是 Live Photo，普通照片不能直接做 Live Sticker ②贴纸库是系统级的，不能在第三方手帐App里调用 ③存在本机，换手机就没了④超过300张后最早创建的会被系统删除

苹果对第三方开发者开放：Visual Look Up API

苹果在 WWDC 2023 专门演示了这个能力——第三方 App 可以用 VNGenerateSubjectLiftMaskRequest（Vision 框架）调用同款抠图模型，在 App 内实现和苹果原生一样的精度。这是 Core ML 模型，完全免费，不付费，不限调用次数（设备上运行）。

📣 二狗判断

苹果原生功能确实强，但有两个核心限制：①它是系统工具，不是创作平台——抠了图，不能存到统一的贴纸库里反复用，不能叠加到手帐画布上创作②没有社交和分享属性——你抠出来的贴纸只有你自己知道，不能分享到广场让别人用你的贴纸。所以苹果做的是"工具"，俺们做的是"平台"。差别就在这里。就像苹果有原生地图，但高德/百度地图依然活得好好的——因为地图不是工具，是生活服务。

苹果原生 vs 俺们的差距

  • ⚠️ 贴纸库较初级可以保存但无分类/标签/搜索
  • ❌ 无手帐画布不能叠加创作
  • ❌ 无跨App调用贴纸存在系统里
  • ❌ 无云同步换手机贴纸全丢
  • ❌ 无社交广场不能分享/使用他人贴纸

俺们的核心优势

  • ✅统一的贴纸库（云端同步）
  • ✅手帐画布创作（叠加/拖拽）
  • ✅社区分享（广场/关注/收藏）
  • ✅品牌素材合作（别人没有的）
  • ✅跨平台（iOS+Android+小程序）

技术方案调整建议

  • iOS直接用 Vision 框架 API，免费且精度与苹果原生一致，无需第三方 API
  • Android用 Google ML Kit Subject Segmentation，免费且在设备上运行
  • 成本抠图 API 成本可以降到 0！只要用户设备支持
  • 旧机型旧款 iPhone/Android 没有神经引擎的用户，仍需要云端 API 兜底
🤖 安卓各厂商能力详细分析
ANDROID OEM CAPABILITIES · DETAILED

各厂商能力参差不齐，俺来逐个拆解

没有统一的"安卓原生贴纸体系"——碎片化既是挑战，也是机会

安卓阵营和苹果完全不同。苹果有统一的 iOS + Vision 框架，安卓则是各厂商各自为战。俺系统梳理了全球主要安卓厂商的能力边界，作为这个想法落地可行性的核心依据。

Google ML Kit免费跨厂商抠图方案
小米 HyperOS 2.0AI Matting 2.0 + 动态贴纸
三星 One UI 7Photo Assist + 自定义贴纸
ColorOS 16AI Eraser + AI Studio
华为鸿蒙HMS AI，封闭生态

🍎 Apple iOS：最强的参照系

iOS 16+（2022年9月）：苹果推出 VNGenerateSubjectLiftMaskRequest，Vision 框架级抠图 API，第三方 App 可调用，精度与原生完全一致，完全免费。任何 iOS 16+ 设备都可以用。

iOS 17+（2023年9月）：Live Stickers，实况照片提取动画贴纸，系统级贴纸库，通过 emoji 键盘在任意 App 使用（含 WhatsApp/Telegram）。但必须是 Live Photo，普通照片不行。

iOS 18（2024年9月）：增强视觉搜索（Enhanced Visual Search），照片可选择上传 Apple 服务器分析（可关闭），隐私可控。

局限性：①贴纸库无分类/标签/搜索 ②300张以上会删除最旧的 ③换手机贴纸全丢 ④不能在手帐画布上叠加创作

🔵 Google Pixel：AI最强，但定位不同

Magic Eraser（物体消除）：Google Photos 内置，圈住不想要的内容→AI消除并填充背景。不是抠图提取，是消除物体——抠出来的东西直接没了，不存在了。

Magic Editor（物体重布局）：移动/缩放/删除照片中的人物或物体，AI生成填充背景。不是提取，是编辑修改。

Best Take：多张照片选择最佳面部表情，合成一张自然合影。

关键问题：Pixel 的 AI 是"消除+重编"，不是"提取+保存"。不能提取主体为 PNG 贴纸。

🟠 小米 HyperOS：进步最快的中国厂商

Photo Cutout（照片提取）：相册→长按主体→Creativity→Cutout，可提取主体，生成透明背景 PNG，可分享。这是真正支持提取+保存为 PNG的中国厂商功能。

HyperOS 2.0（2025年7月更新）：AI Matting 2.0，精度大幅提升，支持多主体分割，可替换背景为动态效果（时间/位置/天气），新增动态贴纸（Animated Stickers）、拼图模板、自定义模板。

局限性：①分享给朋友后即用即弃，没有个人贴纸库 ②不同设备（小米/红米/POCO）能力不一致 ③没有跨 App 调用能力 ④不能在手帐画布使用

🟣 三星 Galaxy AI：功能全，但分散

One UI 6/7 内置 Galaxy AI 相册能力：

① Generative Edit：移动/消除/缩放对象，AI生成填充 ② Edit Suggestions：AI自动识别可优化的内容并推荐 ③ Best Take：面部表情合成 ④ Photo Assist：AI主体识别+重编辑

自定义贴纸（One UI 7）：相册→选择照片→Lasso工具圈选→Save保存为图片。贴纸可以添加到 Gallery，可以设为头像，可以分享。这是三星真正在做"贴纸提取"的地方。

局限性：①Lasso是手画，不是AI自动识别主体 ②没有系统级贴纸库（像iOS那种emoji键盘集成） ③Galaxy AI部分功能需要云端处理 ④贴纸以图片形式存在，无法在第三方 App 里直接调用

🟢 OPPO ColorOS：AI功能丰富，但方向不同

ColorOS 15/16 内置 AI 相册能力：

① AI Eraser：消除照片中不需要的物体（类似Magic Eraser） ② AI Unblur：模糊照片清晰化 ③ AI Reflection Remover：去除玻璃反光 ④ AI Studio：AI生成形象照、风格照等

ColorOS 16（2025年10月）：AI Perfect Shot（多照片合成最佳表情）、Group Photo Composer（AI补全合影缺失人物）。

局限：OPPO的AI方向是"消除"和"合成"，不是"提取+保存为可复用贴纸"。ColorOS没有对标iOS Live Stickers的系统级贴纸功能。

🔷 Vivo OriginOS：进步中，但生态较弱

OriginOS 6（Android 16 base，2025年）：AI 能力大幅提升，但主要方向是 UI 创新和 AI 助手。AI 图像编辑能力相比小米/OPPO 较弱，没有明确的"贴纸提取"功能定位。

局限：Vivo 的 AI 能力主要靠与 Google 合作（Gemini Nano），自有 AI 能力相对少。全球市场份额中 Vivo 主要靠低端机，高端机型的 AI 功能落地较慢。

🔴 华为鸿蒙：能力最强，但最封闭

HarmonyOS / EMUI 内置 AI Cutout：相册中长按主体→提取为贴纸，可以保存到本地。可以去除背景，也支持智能裁剪。

HiAI Foundation（麒麟芯片 NPU）：华为自研 NPU 运行 AI 模型，抠图在设备上完成，功耗低，精度高。从硬件到软件自主可控，技术上非常强。

致命问题：华为手机没有 Google Mobile Services（GMS），ML Kit 无法使用。HMS Core（Huawei Mobile Services）有自己的 AI 能力，但第三方开发者接入门槛高，不兼容国际主流开发框架（如 Capacitor/Flutter 的部分插件）。

📣 落地可行性综合判断

俺来逐个回答：能不能落地？落地效果如何？

iOS：完全可落地。Vision 框架抠图免费高精度，用户基数大（iPhone在中国城市用户中占比40%+），国内 iOS 用户付费意愿强。优先做 iOS 版本。

小米：可以落地。HyperOS 2.0 的 AI Matting 2.0 和动态贴纸功能跟俺们的方向高度重合，用户已经有"贴纸提取"的使用习惯，教育成本低。可以直接对接小米生态做联合。

三星：可以落地。Galaxy 用户（尤其S系列/Z折叠屏）消费能力强，愿意为创作付费。但三星没有系统级贴纸库，俺们的"统一贴纸库+画布创作"对他们有真实价值。

OPPO：部分可落地。AI Eraser 方向偏消除，不是提取。需要评估是否有贴纸提取 API。ColorOS 16的 AI Studio 可能提供更多能力。

Vivo：较难落地。AI 能力相对弱，OriginOS 碎片化，第三方开发资源少。

华为：最难落地。虽然技术能力强，但 GMS 缺失导致技术方案完全独立，开发成本高。建议后期（用户量上来后）单独做华为版本，用 HMS Core + 鸿蒙专属 API。

🍎 iOS：Vision 框架（唯一方案）

SDK：Vision.framework（系统内置，无需安装，无需申请，无需付费）

核心API：VNGenerateSubjectLiftMaskRequest

调用方式（Swift，10行代码）：

import Vision
// 1. 加载图片
let inputImage = CIImage(cvPixelBuffer: pixelBuffer)
// 2. 创建请求
let request = VNGenerateSubjectLiftMaskRequest()
// 3. 执行请求
let handler = VNImageRequestHandler(ciImage: inputImage)
try handler.perform([request])
// 4. 获取结果（mask）
if let result = request.results?.first {
    let maskPixelBuffer = result.generateScaledMaskForImage(for: result observation, pixelFormat: .integer32)
    // 5. 应用mask到原图 → 透明背景PNG
}

关键信息：

  • 无需申请，无需配置，Xcode内置
  • iOS 16+ 所有设备支持
  • 完全免费，不限调用次数
  • 在设备上运行（Neural Engine），无需联网
  • 支持多主体分割（iOS 17+）
  • Capacitor 官方插件支持：@capactor-mlkit/subject-segmentation（iOS端调用的就是Vision）

🤖 Android：Google ML Kit（主方案）

SDK：com.google.mlkit:subject-segmentation（Google官方，需添加依赖）

Gradle依赖（Android）：

// build.gradle
dependencies {
    implementation("com.google.mlkit:subject-segmentation:16.0.0-beta1")
}

Kotlin代码（10行）：

// 1. 从Bitmap创建InputImage
val image = InputImage.fromBitmap(bitmap, 0)
// 2. 创建分割器
val segmenter = SubjectSegmenter.getClient(
    SubjectSegmenterOptions.newBuilder()
        .enableForegroundBitmap()  // 主体前景图（抠好啦）
        .build()
)
// 3. 执行
segmenter.process(image)
    .addOnSuccessListener { result ->
        val foregroundBitmap = result.foregroundBitmap
        // foregroundBitmap 就是抠好的透明背景图！
    }

关键信息：

  • 完全免费，无需API Key
  • 在设备GPU上运行，不需要联网
  • 需要 Google Play Services（国内手机可能没有）
  • 支持多主体分割
  • 跨平台：Android + iOS（通过ML Kit）

🔗 跨平台开发：Capacitor（俺们推荐的方案）

如果用 Capacitor（前端代码跑 iOS/Android/小程序），有官方插件直接对接 ML Kit，不需要写原生代码：

插件：@capacitor-mlkit/subject-segmentation

// 安装
npm install @capacitor-mlkit/subject-segmentation
npx cap sync

// TypeScript 调用
import { SubjectSegmentation } from '@capacitor-mlkit/subject-segmentation';

const result = await SubjectSegmentation.processImage({ path: 'photo.jpg' });
console.log(result.path); // 抠好后的PNG路径

为什么推荐 Capacitor：

  • 一套代码跑 iOS + Android + 小程序 + Web
  • iOS 端调用 Vision 框架，Android 端调用 ML Kit
  • 封装好，不需要写原生代码
  • 插件官方维护，支持 Capacitor 7
  • Flutter 用户可用 google_mlkit_subject_segmentation（pub.dev）

📱 各厂商独立SDK情况

小米：HyperOS 的抠图能力没有官方对外 SDK，是系统级功能。第三方 App 无法直接调用，只能通过用户手动在相册里操作后，再从相册分享出来（通过系统分享面板）。但 HyperOS 2.0 新增了开发者 API，具体需要申请内测资格。

三星：Galaxy SDK 主要提供 IAP（内购）和远程测试实验室，没有专门的抠图 SDK。三星的 AI 抠图能力（Photo Assist）不对外开放。

OPPO：ColorOS 的 AI Eraser 同样没有官方对外 SDK，AI 能力封装在相册 App 里，不对第三方开放。

华为：HMS Core 有华为自己的 ML Kit（HiAI），但跟 Google ML Kit 不兼容，需要单独接入。文档是中文的，但社区资源少，国际化程度低。

Google Pixel：Magic Eraser 是 Google Photos 内置功能，没有 SDK，但 Google ML Kit 本身就在 Pixel 上运行，所以用 ML Kit 在 Pixel 上效果最好。

📣 俺的建议

结论很清楚了：

有官方SDK的：

  • 🍎 iOS → Vision 框架（免费，系统内置，最稳定）
  • 🤖 Android → Google ML Kit（免费，官方维护）

没有官方SDK的：

  • 小米/三星/OPPO → 用 Google ML Kit 兜底，这些厂商的系统本身也跑的是 Google ML Kit 或类似模型
  • 华为 → 用 HMS ML Kit（独立接入）或 Google ML Kit（如果HMS被规避）

最务实的做法：直接用 ML Kit + Vision 做抠图，放弃对接各厂商私有SDK。ML Kit 精度已经足够好，而且跨所有 Android 厂商，不需要为每个厂商单独适配。

📌 二狗最终判断

🏁 综合评估

这个想法值得做，理由如下：

① 差异化清晰：不做素材库模板，做用户原创。醒图/轻颜是工具，这个是"创作平台"，逻辑不同。

② 技术成熟且成本趋零：iOS 用苹果 Vision 框架（VNGenerateSubjectLiftMaskRequest）抠图完全免费，精度与苹果原生一致。Android 用 Google ML Kit 同样免费。API 成本可以降到 0。

③ 小红书天然传播：用户自己拍的手帐图片天然适合发小红书，可以省大量推广费。

④ 护城河够宽：一旦用户积累了几百张自己的贴纸，迁移成本极高够高，用户不会轻易换平台。

⑤ 小程序验证成本低：微信小程序可以快速验证，不需要做App Store审核。

⚠️ 核心风险

最大的风险不是醒图跟进，而是产品定位不清。苹果已经做了免费抠图，俺们的差异化必须体现在"创作"而不是"提取"。如果只做"更好的抠图工具"，那是跟苹果正面竞争，死路一条。但如果是"原创手帐平台"，那就是另一个故事了。

🚀 下一步行动建议

如果大哥真的要推进，俺建议：第一件事，先测试苹果 Vision 框架的抠图精度（免费），用 iPhone 照片实测——如果精度够用，就不需要 BRIA RMBG 了，成本大幅降低。等 iOS 端跑通了，再做 Android 端 ML Kit 的方案对比。

一句话总结

想法有价值，差异化够，技术成熟。建议先做抠图精度测试，再决定是否投入开发。
